# SentinelAC 2

Серверный античит для **Paper 1.21.11** (Java 21). Без зависимостей: работает на событиях Paper.

* Готовый плагин: [`release/sentinel-anticheat-2.0.0.jar`](release/sentinel-anticheat-2.0.0.jar)
* Сборка: `./gradlew build` → `build/libs/`

## Установка

1. Положите jar в `plugins/` и перезапустите сервер.
2. Первые дни рекомендуется `mode: monitor` в `plugins/SentinelAC/config.yml`: античит только уведомляет,
   ничего не отменяет и не кикает. Посмотрите уведомления, при необходимости подстройте пороги, затем
   переключите на `mode: enforce` и выполните `/sentinel reload`.

## Как это работает

Клиент Minecraft 1.21.2+ в конце **каждого** своего тика отправляет пакет `client_tick_end`, а Paper
обрабатывает все игровые пакеты игрока строго по порядку. Поэтому сервер точно знает, что произошло
внутри одного тика клиента: смена слота, удар, взмах руки, движение. На этом построены главные проверки.

| Проверка | Что ловит | Как |
|---|---|---|
| **AutoSwap** | Макросы auto attribute swap | Ванильный клиент отправляет смену слота **до** удара. Смена слота **после** удара в том же тике обычным клиентом невозможна. После срабатывания на `penalty-seconds` отменяются удары со сменой слота перед ними, и макрос перестаёт давать преимущество |
| **MultiAura** | Killaura по нескольким целям | Две разные цели в одном тике клиента |
| **NoSwing** | Удары без анимации | Удар без пакета взмаха руки в том же тике |
| **Reach** | Увеличенная досягаемость | Дистанция до хитбокса больше атрибута `entity_interaction_range`. По игрокам используется история их позиций за время пинга атакующего, поэтому лаг не наказывается |
| **Fly** | Полёт, зависание, прыжок в воздухе, планирование | Каждый тик вертикальное движение сверяется с гравитацией: `dY ≤ (dY_прошлого − g) × 0.98`. Зависание без пакетов движения тоже ловится, потому что проверка идёт по тикам, а не по `PlayerMoveEvent` |
| **Speed** | Ускорение | Горизонталь сверяется с ванильным трением, ускорением и атрибутом скорости (бег, зелья, Soul Speed, лёд) |
| **NoSlow** | Нет замедления при еде, луке, щите | Та же модель с множителем ввода 0.2 |
| **Timer** | Ускоренный клиент | Баланс «время клиента − реальное время». Задержки сети засчитываются в ограниченный долг, лаги сервера сбрасывают баланс |
| **BlockReach** | Установка блоков издалека | Дистанция до кликнутого блока больше `block_interaction_range` |
| **AirPlace** | Установка блока «на воздух» | Клик по пустому месту (обычный клиент кликает только по блокам) |
| **Scaffold** | Мост под собой с взглядом вперёд | Блок под ноги при наклоне камеры меньше `max-pitch` |
| **BadPackets** | Невозможный угол камеры | Наклон больше 90° |

Поблажки, чтобы честные игроки не страдали: отбрасывание (удары, взрывы, заряды ветра, удочка) на время
пинга, телепорты, эндер-жемчуг, тиф, элитры, вода, лава, лестницы, лианы, строительные леса, паутина,
пудровый снег, слизь, мёд, кровати, поршни, лодки и толкающие сущности. Окружение сканируется только
при подозрении, в обычном тике проверка стоит один запрос коллизий и чтение одного блока.

Клиенты, которые не шлют `client_tick_end` (старые версии через ViaVersion), проверками по тикам
(движение, Timer, AutoSwap, MultiAura, NoSwing) не проверяются вообще: точную последовательность
у них восстановить нельзя, а неточная дала бы ложные срабатывания. Reach, BlockReach, AirPlace и
Scaffold работают для всех.

## Команды и права

| Команда | Право | Описание |
|---|---|---|
| `/sentinel alerts` | `sentinel.alerts` | Вкл/выкл уведомления (сохраняется после перезахода) |
| `/sentinel profile <игрок>` | `sentinel.alerts` | Нарушения игрока и тип проверки клиента |
| `/sentinel reload` | `sentinel.admin` | Перечитать `config.yml` |

`sentinel.bypass` (по умолчанию OP) — обход всех проверок; `sentinel.bypass.<проверка>` — одной проверки
(`sentinel.bypass.fly`, `sentinel.bypass.reach` …).

## Настройка

У каждой проверки в `config.yml`: `enabled`, `buffer` (сколько подозрительных событий нужно для
срабатывания), `buffer-decay`, `vl`, `kick-vl` (0 = не кикать) и `mitigate` (отменять/откатывать), плюс
свои параметры (`tolerance`, `max-pitch`, `threshold-ms` …). Некорректные значения не ломают плагин:
используется значение по умолчанию, в консоль выводится предупреждение.

Кик по умолчанию включён только у проверок с минимальным риском ложных срабатываний: AutoSwap (VL 6),
MultiAura (8), NoSwing (10), Fly (20), BadPackets (6), AirPlace (8). Остальные отменяют действие или
откатывают игрока и уведомляют администрацию.

## Тестирование

**Unit-тесты (20, `./gradlew test`).** Физика проверяется на ванильных траекториях: ходьба, бег, 600
тиков непрерывных прыжков с разбега, прыжки на льду, медленное падение. Ни один честный тик не выходит
за границы, а зависание, прыжок в воздухе, планирование, ускорение на 30 % и NoSlow выходят. Также
покрыты последовательности AutoSwap, баланс Timer (джиттер, лаг с догоняющей пачкой, ускоренный
клиент), история позиций и разбор конфига.

**Paper 1.21.11 (build 132), боты на mineflayer**, эмулирующие поведение ванильного клиента 1.21.11:

* честная игра (ходьба, бег и прыжки с разбега в 4 направлениях по рельефу, прыжки, смена слота с
  ударом в одном тике), 5 прогонов, в режиме `enforce` в том числе: **0 нарушений**;
* сработали: AutoSwap (4 из 4, кик на VL 6; после первого срабатывания удары макроса отменяются),
  MultiAura, NoSwing, Reach (3.45 > 3.0), Fly (зависание, кик на VL 20), Speed (0.6 блока/тик),
  Timer (~28 тиков/с), Scaffold, AirPlace, BlockReach (4.81 > 4.5);
* после 9 входов и выходов в памяти 0 объектов данных игроков.

Не проверено вживую: настоящий ванильный клиент (боты — эмуляция), отбрасывание от зарядов ветра,
тиф, элитры, многопользовательская нагрузка.

## Известные ограничения

* Модель движения консервативна (верхние границы), поэтому мелкие ускорения в пределах допусков
  (`tolerance`) не ловятся. Это осознанный выбор в пользу отсутствия ложных срабатываний.
* Поблажка на отбрасывание выдаётся на время пинга игрока, и в это окно читер может слегка ускориться.
* Откат возвращает игрока на последнюю позицию, где он стоял на земле и прошёл все проверки.
